# 四场模拟面试与复盘模板

以下是训练脚本，不是任何公司的真实流程。每场先回答再看讲义，面试官按答案选择追问，不要一次把所有问题念出来。

## A 场：Java 后端技术面（60 分钟）

- 0～5 分钟：自我介绍，只讲与目标岗位相关的经历。
- 5～20 分钟：从 HashMap 可变 key 或线程池耗尽切入，追问共享状态、JMM、取消与背压。
- 20～35 分钟：Spring 事务失效 → MySQL 隔离/锁 → 更新冲突与索引。
- 35～50 分钟：消息重复投递 → 外部副作用 → 重试和对账。
- 50～55 分钟：一个 JVM/网络慢请求排障题。
- 55～60 分钟：候选人反问与复盘。

**主问题**：下单接口引入并发调用后变慢，CPU 只有 30%，为什么？

**追问分支**：答线程池则追队列与拒绝；答数据库则追连接持有时长与事务范围；答网络则追 deadline 与重试。要求证据区分原因。参考：03、05、06、10、12 章。

## B 场：现场编码（45 分钟）

**题目**：实现容量固定的 LRU，要求 get/put 平均 O(1)，更新 key 会刷新最近使用顺序。先解释单线程版本，再讨论多线程和容量 0。

- 5 分钟澄清：返回值、空值、key 类型、并发要求。
- 8 分钟思路：哈希表 + 双向链表；明确链表头尾含义。
- 22 分钟编码：覆盖新增、更新、命中、淘汰、空容量。
- 5 分钟验证：容量 2；put A/B → get A → put C，应淘汰 B。
- 5 分钟拓展：锁粒度、热点、TTL、内存权重、淘汰近似与工程库的区别。

参考：14 章。学习示例的 LinkedHashMap 版用于理解行为；手写训练应自己实现节点和链表，不直接调用现成 LRU。

## C 场：系统设计与项目（75 分钟）

**题目**：为多租户 SaaS 设计订单提交、异步履约和状态查询。题设：100 万日活，平均每人每天 2 次提交，峰值为日均的 20 倍，每订单正文约 2KB，状态保留一年。数字仅用于训练。

- 先估算：2,000,000/86,400 ≈ 23.1 次/秒，峰值约 463 次/秒；原始正文约 4GB/日，年约 1.46TB，索引/副本/日志/查询流量另计。
- 定义模型：订单 ID、租户、用户、幂等键、状态/版本、事件 ID；明确唯一约束。
- 设计 API：创建、状态查询、取消；同一幂等键不同 payload 如何处理。
- 主链路：订单与 outbox 同事务；发布可重试；消费业务效果去重；状态可查询。
- 加约束：某一大租户占峰值 60%，一个履约方超时 30 秒；如何隔离、限流和恢复。
- 项目连接：你以前做过哪个类似判断？当时证据是什么？哪些只是这里的设计推演？

不要求上来就微服务/分库；该规模能否由简单架构承载，应根据实际读写与压测决定。参考：09、11、12、19 章。

## D 场：Agent 工程面（60 分钟）

**题目**：设计企业知识与工单助手，可检索知识、查看工单、申请退款；退款须按业务政策确认和授权。

- 0～10 分钟：哪些步骤是确定性 workflow，哪些需要模型判断？
- 10～20 分钟：检索如何分租户/权限？如何处理过期文档和冲突证据？
- 20～35 分钟：工具契约、参数校验、授权、审批、幂等与持久化状态。
- 35～45 分钟：退款已成功但工具响应丢失，系统重启后如何恢复？
- 45～55 分钟：用什么评测集区分回答质量和任务成功？成本如何算？
- 55～60 分钟：给一个 prompt injection 负例及预期行为。

参考锚点：权限由执行系统保证；不把 retrieved text 当指令；退款效果通过业务状态验证；模型输出和工具结果分开记录；成功/失败/不确定不能混为一谈；成本分母需要说明。参考：15～18 章。

## 通用复盘记录

复制到 [个人复盘模板](../practice/review-template.md) 中填写。

| 维度 | 记录 |
| --- | --- |
| 我原话说了什么 | 保留关键原句，不美化 |
| 面试官实际追问 | 是概念、边界、证据还是沟通 |
| 错误类型 | 知识错误 / 推理跳跃 / 缺实践 / 表达混乱 |
| 修正版回答 | 结论 → 机制 → 条件 → 例子 → 验证 |
| 下一次验证 | 闭卷重答、代码、实验或补项目证据 |
| 下次复习日 | 自行填写 |

评分按 02 文档的 0～4 分行为尺。一次模拟只选最重要的三个改进项，否则下次仍可能重复同样问题。
