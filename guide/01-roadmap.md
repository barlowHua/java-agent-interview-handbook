# 学习路线：先补短板，再扩广度

本版提供 12 周主干节奏与 16 周完整专题路线。12 周主干假设每周 8～10 小时；完整路线可按每周 10～15 小时预留，并按诊断结果延长。它是安排模板，不是掌握时长承诺。每天固定 20～30 分钟编码或闭卷回忆；若过关标准没达到，应延长本阶段，而不是机械翻页。

## 模块地图与依赖

| 路线 | 顺序 | 核心产物 |
| --- | --- | --- |
| Java 执行基础 | 01 语言 → 02 集合 → 03 并发 → 04 JVM → 05 Spring | 一份并发实验记录与一次 JVM 排障推演 |
| 数据与一致性 | 06 MySQL → 07 Redis → 08 消息 → 09 分布式 | 两个并发事务时间线与一张 Outbox 状态图 |
| 系统工程 | 10 网络/OS → 11 系统设计 → 12 可靠性 → 13 安全交付 | 一份有容量假设、失败处理和回滚的设计 |
| 编码与表达 | 14 算法、19 项目，贯穿全程 | 计时编码记录与两份真实项目叙事 |
| Agent 工程 | 15 LLM → 16 RAG → 17 Agent → 18 生产工程 | 一套有负例的评测集与工具副作用恢复设计 |

Java 与数据库基础是 Agent 工程的支撑：调用模型也需要连接池、并发预算、权限、持久化和可观测性。不要只记框架类名。

## 12 周主线

| 周 | 主题与章节 | 本周必须交付 | 过关后再继续 |
| --- | --- | --- | --- |
| 1 | 诊断；01～02 | 能解释 equals/hashCode、泛型边界、HashMap；完成二分与哈希题 | 不看答案准确口述 6 题 |
| 2 | 03 并发 | 跑并发实验；设计有界线程池；解释取消和共享状态 | 能分析一个丢更新与一个线程池耗尽案例 |
| 3 | 04～05 JVM/Spring | 一页内存分类、事务失效复现方案 | 能区分堆、直接内存和容器内存；说明代理边界 |
| 4 | 06 MySQL | 索引设计、EXPLAIN 分析、事务交错图 | 对慢查与死锁给出可验证的定位路径 |
| 5 | 07～08 缓存/消息 | 缓存失效时间线、消费幂等设计 | 不把投递保证等同业务效果恰好一次 |
| 6 | 09～10 分布式/网络 | 完成 Outbox 实验；画超时重试与鉴权链路 | 解释“超时但已成功”及恢复办法 |
| 7 | 11～12 设计/可靠性 | 完整设计一个订单系统；写事故推演 | 有估算、有瓶颈、有观测和降级 |
| 8 | 13/19 安全/项目 | 租户越权测试矩阵；真实项目一和失败复盘 | 所有结果能区分事实、估算和推测 |
| 9 | 15 LLM 基础 | token/上下文预算、流式响应状态图 | 讲清模型能力与执行系统责任 |
| 10 | 16 RAG | 设计分块、混合检索、重排和 ACL；建立评测集 | 区分检索错、生成错、权限错 |
| 11 | 17～18 Agent | 完成离线评测；设计状态机、审批、幂等和恢复 | 能定位一次失败与估算单任务成本 |
| 12 | 四场完整模拟 | 编码、设计、项目、Agent 各一场；复盘补漏 | 连续两轮满足自测线，仍按目标 JD 补差 |

每周编码题从 14 章题单按模式推进，不集中拖到最后。每周至少一次 5 分钟项目口述，逐渐替换泛泛描述。

## 扩充版：16 周完整专题路线

本路线把主干与深挖按主题配对，**不是先把01～19读完再顺序背20～34**。每天保留编码，星期末用闭卷口述决定是否继续；一周材料多时拆成两周。

| 周 | 配对章节 | 深度目标与产出 |
|---|---|---|
| 1 | 01、02、20 | 语言与集合；引用图、泛型签名、异常/精度边界 |
| 2 | 03、21并发部分 | AQS/CAS、ThreadLocal、线程池；完成实验01 |
| 3 | 04、21运行时部分 | 类加载、JIT、GC；一份CPU与内存诊断树 |
| 4 | 05、22 | Spring/MyBatis；事务代理与请求链路推演 |
| 5 | 06、23 | 索引、MVCC、锁、日志；9组SQL手算与运行 |
| 6 | 07、24缓存部分 | 编码、持久化、复制、缓存一致性；构造竞态 |
| 7 | 08、09、24消息部分 | 消息语义、共识、Outbox；完成实验02 |
| 8 | 10、25、29 | 网络/OS、治理、搜索；一次请求全路径与搜索可见性 |
| 9 | 11、30、33前半 | 容量、领域边界、订单/支付设计；完成一页ADR |
| 10 | 12、13、31、34排障 | 稳定性、安全、发布；一次故障模拟与兼容迁移 |
| 11 | 15、26 | 模型结构、推理与训练选型；KV与token成本演算 |
| 12 | 16、27 | 检索、权限、记忆与指标；建立有负例的数据集 |
| 13 | 17、28 | Agent状态、工具与协议；UNKNOWN恢复与审批设计 |
| 14 | 18、33 Agent案例 | 评测、安全、成本与灰度；完成实验03与综合设计 |
| 15 | 19、34项目/协作 | 两份真实项目叙事、一份失败复盘；补证据缺口 |
| 16 | 14、32及全量矩阵 | 四场模拟、计时编码、覆盖矩阵抽查与错题回补 |

第14、32章贯穿每一周，不留到第16周才开始；第16周用于综合验收。纯后端岗位可把11～14周中模型训练细节降为P2，把时间分给目标岗位最相关的数据库、中间件和系统设计；Agent岗位保留这四周实践。首次完成整轮后，按错题复习，不再机械从第一页重读。

## 两条岗位分支

**Java 资深后端主线**：前八周优先保障，15～18 章先完成 L1/L2。剩余时间深入自己实际使用的数据库、中间件、业务一致性与迁移策略。不要把所有框架都学一遍。

**Java + Agent 应用工程主线**：前八周里已达标模块可以压缩，把时间转给 15～18 章和综合项目。Agent 实践至少包含一个有状态工具流程、租户检索权限、一组失败样本、一份成本和延迟记录。仅用提示词串起聊天界面还不能展示完整工程能力。

## 已临近面试：14 天复习路径

适用于原本已有基础、需要组织表达的人，不适用于从零掌握全部内容。

- 第 1～2 天：诊断、项目叙事、集合/并发、每日一道代码题。
- 第 3～4 天：JVM/Spring、事务与线程池故障。
- 第 5～6 天：MySQL/Redis，做时间线推演。
- 第 7～8 天：消息/分布式，完成 Outbox 实验。
- 第 9～10 天：网络/可靠性/安全，做一个完整系统设计。
- 第 11～12 天：Agent 岗复习 15～18；后端岗继续核心业务设计与数据库排障。
- 第 13 天：按目标岗位做 90 分钟模拟，严格计时。
- 第 14 天：只补高风险短板，核对履历中的事实与数据，整理反问。

## 每周复盘表

| 项目 | 填写内容 |
| --- | --- |
| 本周真正能闭卷解释的三点 | 写具体机制，不写“学习了 Redis” |
| 本周最容易混淆的两点 | 如可见性和原子性、重试和恢复 |
| 一条代码/实验/文档证据 | 路径、输入、实际输出、解释 |
| 一个失败的假设 | 我原先以为……证据表明…… |
| 下周优先级 | 最多三个，写出验收方式 |

若“读过很多、编码和模拟都没做”，下周停止新增章节，先补输出。复习计划服务于能力证据，不服务于打卡数量。
