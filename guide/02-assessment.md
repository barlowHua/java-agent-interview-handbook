# 入学诊断与过关标准

先闭卷作答，再看后面的锚点。这个分数只用于确定学习顺序，不预测公司录用结果。每题给自己 3 分钟，选两个最熟悉的问题继续追问 5 分钟；总计约 55 分钟。若今天只有 20 分钟，先做 1、3、5、9、12、15 题。

## 统一评分尺

| 分数 | 行为证据 |
| --- | --- |
| 0 | 无法回答或关键概念错误 |
| 1 | 能给定义，但无法解释原因与边界 |
| 2 | 机制正确，能回答常见追问与反例 |
| 3 | 能在情境中应用，给出验证方法和失败处理 |
| 4 | 能比较方案、说明代价，有真实或实验数据支撑 |

表达不流畅与知识错误分别记录。不要因为很自信就加分，也不要把听起来复杂当作正确。

## 十五道诊断题

1. HashMap 为什么需要 equals 和 hashCode 一致？可变 key 会发生什么？
2. volatile 能解决哪些问题，为什么不能让 `count++` 原子化？
3. 接口超时，CPU 不高，线程池和数据库连接池都很忙，如何定位？
4. Spring 一个 public 方法调用本对象另一个带事务注解的方法，事务一定生效吗？
5. 给订单列表设计联合索引，如何验证不是“看起来用了索引”？
6. 数据库更新成功但缓存删除失败，怎样定义和缩小不一致窗口？
7. 消费者写库成功但提交 offset 前崩溃，如何避免业务重复生效？
8. 网络分区时，库存扣减能否同时承诺所有请求立即成功与库存绝不超卖？先明确语义。
9. 设计订单创建服务：估算容量、数据模型、幂等、消息与恢复。
10. 写出二分查找第一个大于等于 target 的位置，解释循环不变量。
11. 用户修改订单 ID 能读取别人订单，应该在哪里校验什么？
12. 介绍一次亲自解决的复杂问题：你的决策、被否决方案、证据与结果。
13. 为什么长上下文不一定能替代 RAG？什么时候检索反而无益？
14. Agent 调用付款工具后超时，恢复时能否重新执行？
15. Agent “回答流畅但业务成功率低”，你如何拆解指标并定位？

## 答案锚点：答完再核对

1. equals 相等必须有相同 hash；查找先定位桶再判等；修改影响 hash/equals 的字段会破坏查找约定。见 01/02。
2. 可见性与指定顺序保证不等于复合操作互斥；说明 happens-before、锁或原子类的选择。见 03。
3. 区分排队与执行；看等待栈、借出连接时长、慢事务、下游耗时与近期变更，先止损再验证。见 03/10/12。
4. 默认代理方式的自调用不经过代理；还需看事务管理器、异常类型、事务传播和线程边界。见 05。
5. 根据过滤、排序、选择性和数据量设计；对照实际扫描行数、回表、排序、锁与耗时，不只看 key 字段。见 06。
6. 承认窗口，给出重试/失效传播/版本控制/TTL/回源等策略及一致性目标；强一致需求不能仅靠缓存失效口号。见 07。
7. 稳定业务键与事务内去重和业务写入；offset 和外部副作用不能凭配置自动变成一个原子事务。见 08/09。
8. 先限定一个库存对象与一致性要求，再说明分区下拒绝/等待或降低约束的选择；业务可用性与 CAP 可用性不要混用。见 09。
9. 先问约束，再估算平均/峰值/存储；建模状态机和唯一键；设计失败、恢复、观测和扩展。见 11。
10. `[lo, hi)`，lo 左边都小于 target，hi 及右边都大于等于 target；每轮收缩，返回 lo；空数组和重复值。见 14。
11. 服务端可信身份 + 租户/对象/动作授权；贯穿缓存、批量、导出、后台任务。见 13。
12. 区分团队与个人、事实与估算；展示约束、备选、验证、结果、残余风险；不补造数据。见 19。
13. 外部知识更新、权限、定位、成本与上下文利用；小而稳定资料可能直接放上下文；通过评测选型。见 15/16。
14. 超时代表结果不确定；稳定业务操作 ID、查询结果、幂等副作用、持久化状态及人工恢复。见 17/18。
15. 把检索、规划、工具选择、参数、授权、执行、恢复、最终业务目标拆开；建立负例集和 trace，不只看模型评分。见 18。

## 如何排学习顺序

- Java 主线把 1～12 题视为核心诊断；Agent 主线加上 13～15。
- 先修所有 0 分与关键概念错误，再把核心题推进到 2 分。
- 选与自己主责项目最相关的两类到 3～4 分，用实验或真实事实证明。
- 得分高但编码不通过、项目事实不清晰、核心安全边界错误，都需要单独补课，不能用其他题高分抵消。

## 模块过关线（本项目自测）

随机抽本章三题，至少两题能到 2 分；完成本章练习并解释实际结果；能指出一个结论的适用条件和一个反例。P0 的主责领域再加一个 3 分场景题。读过或背出同样措辞不自动算通过。

## 最终模拟自测线

| 项目 | 观察内容 | 自测标准 |
| --- | --- | --- |
| 编码 | 思路、边界、正确性、复杂度、沟通 | 45 分钟完成一道适配水平的中等模式题及边界验证 |
| 原理 | 定义、机制、反例、工程连接 | 核心随机题无概念性错误，能接两轮追问 |
| 系统设计 | 约束、模型、容量、失败、取舍 | 45 分钟内形成端到端方案并应对一次约束变化 |
| 项目 | 个人贡献、证据、判断、复盘 | 5 分钟主叙事 + 20 分钟追问，不编造事实 |
| Agent 岗追加 | 评测、工具安全、恢复、成本 | 能定位失败阶段，给出可执行改进与验证 |

连续两轮达到这些标准，可以开始用具体目标公司的 JD 和面试反馈校准。不要把该自测线解释为企业官方标准。
