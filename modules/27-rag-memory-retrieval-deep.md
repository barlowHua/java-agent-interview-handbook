# 27｜RAG 深入：检索、知识更新、评测与记忆

定位：Agent 应用工程 P1；索引算法的实现推导属于 P2。前置：[16 章](16-rag.md)、倒排索引、向量距离、缓存与权限控制。目标是能把“回答不好”定位到具体环节，并说明改法的代价。资料核对：2026-10-04；索引参数、过滤执行方式和协议能力需以所用产品版本为准。

## 主题覆盖清单

- 表达与排序：BM25、稠密向量、对比训练、距离、ANN、HNSW、IVF/PQ、RRF、重排。
- 数据与知识：查询改写、分块、父子块、表格/代码解析、更新删除、ACL、缓存失效。
- 评测与推理：Recall、Precision、MRR、nDCG、证据覆盖、引用、GraphRAG、多跳问题。
- 状态与记忆：会话上下文、事实记忆、检索知识、过期与纠错、模型和索引迁移。
- 必须产出：一条带权限与版本的检索链路、一份分层评测集、一例“召回正确仍答错”。

## L1｜先把六种问题分开

| 现象 | 首先检查 | 常见但不充分的改法 |
|---|---|---|
| 原资料没有答案 | 知识覆盖、更新时间 | 盲目调大 top-k |
| 资料存在但召回不到 | 分词、向量模型、索引、查询 | 直接换生成模型 |
| 候选含答案但被挤出 | 融合、重排、上下文预算 | 无上限塞入上下文 |
| 证据充足仍答错 | 提示、归因、模型、任务拆解 | 只报 Recall 提升 |
| 引用存在但不支持结论 | claim 与证据逐项对应 | 只验证 URL 能打开 |
| 答案正确却暴露资料 | ACL、外发、缓存、日志 | 让模型“不要泄密” |

检索优化的目标不是让相似度更高，而是让当前用户在当前时间得到完成任务所需的可用证据。证据粒度、授权主体、知识版本和评测分母，需要一起定义。

## L2｜双链路、排序与指标

![离线知识处理和在线带权限检索的双链路](assets/16-rag-pipeline.svg)

**读图顺序：**先走上层文档入库，再从在线身份走到检索、重排与回答。**关键记忆点：**索引是派生视图，授权依据来自可信身份和源数据策略。**简化边界：**图未展开索引分片、异步重建与不同过滤计划；权限过滤必须在未授权内容进入外部重排器、模型或用户前完成。**闭卷重画：**加入一次“文档撤权”和一次“embedding 换版”，标出旧缓存、旧索引与在途请求如何处理。

BM25 可以按词累加理解：`IDF(t) × tf(t,d)(k₁+1) / [tf(t,d)+k₁(1−b+b|d|/avgdl)]`。`tf` 是词在文档中的频次，`|d|` 是长度，`avgdl` 是平均长度；`k₁` 控制频次饱和，b 控制长度归一化。IDF 使罕见词通常贡献更大，但具体平滑公式可能因实现而异。不是出现十次就一定比一次重要十倍。[BM25 教材](https://nlp.stanford.edu/IR-book/html/htmledition/okapi-bm25-a-non-binary-model-1.html)

RRF 可写成 `score(d)=Σ 1/(c+rankᵢ(d))`：对文档 d 在多个结果列表中的名次贡献求和；未出现则该列表贡献为零。c 是融合参数，不是文档相关概率。它绕开不同检索器原始分数的标度差异，但无法证明候选集合包含必要证据。[Elasticsearch RRF 文档](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/reciprocal-rank-fusion)

![一次检索中召回、首条命中、证据支持和业务完成的差异](assets/16-rag-evaluation.svg)

**读图顺序：**先确定必需证据 A/B，再检查实际候选、回答断言与最终任务。**关键记忆点：**命中一个答案不等于覆盖全部证据，引用多也不等于每句话有依据。**简化边界：**示例只有一个查询；宏平均是先逐查询计算再平均，微平均是合并计数后计算。**闭卷重画：**构造 Recall 为 1 但 groundedness 小于 1 的例子，并说出下一步应改检索还是生成。

对于分级相关性，可定义 `DCG@k=Σ(2^relᵢ−1)/log₂(i+1)`，再除以理想排序的 IDCG 得到 nDCG。`relᵢ` 是第 i 条结果的人工相关等级；等级体系和增益函数必须先约定。没有相关文档的查询怎样计分也要明确，不能在报告里悄悄删除难题。

## L3｜二十道深入问答

### Q1：BM25 为什么仍值得保留？

**参考回答：**BM25 基于词项匹配、逆文档频率、词频饱和和长度归一化，不需要把问题与文档编码到同一个稠密空间。它对订单号、错误码、产品型号等精确标识常有价值，排查时也容易看出哪些词产生贡献。但分词、同义词与表达变化会影响召回，不能只凭词面覆盖语义需求。我会在领域查询集上分别测试词法和向量检索，再决定是否混合；不会因为用了大模型就删除词法基线，也不会声称 BM25 对所有专有名词必胜。

**追问：中文怎么做？**要核对分词器、领域词典、字符切分及标识符保留策略；分词不一致可能让看似相同的词根本无法匹配。

### Q2：倒排索引和向量索引到底索引了什么？

**参考回答：**倒排索引把词项映射到包含它的文档及位置、频次等信息，便于按词找候选并计算词法相关性。向量索引组织文档或分块的稠密表示，支持按距离或相似度寻找近邻。两者处理的表达和访问路径不同，可以同存一份逻辑知识，也可以分别维护派生索引。工程中必须保留共同的文档与块标识、版本和授权元数据，否则合并去重、删除同步与引用回溯会出错。选型先看查询特征和规模，而不是把其中一种当另一种的升级版本。

**追问：索引是不是事实源？**通常不是。源文档及其版本是事实依据，索引可以滞后、丢失或重建，不能用索引缺失直接证明业务对象不存在。

### Q3：检索 embedding 怎样学到“相关”？

**参考回答：**检索模型常通过问题与正例文档拉近、与负例文档拉远的训练目标学习表示。正负样本定义决定它把什么看成相关：主题相似、答案包含或业务可用不是同一目标。负例过于简单可能学不到细粒度区分，错误负例又会把实际相关内容推远。我会优先检查领域评测与样本质量，再考虑适配模型；同时遵守模型要求的 query/document 模板和归一化方式。不能因为向量维度更大或通用榜单更高，就断定本业务检索更准确。

**追问：hard negative 有什么风险？**它能训练相似但不相关的区分，也更容易包含假负例；应审核标签并防止把同一答案的不同表述误作负例。[DPR 论文](https://arxiv.org/abs/2004.04906)

### Q4：余弦、点积和欧氏距离能随便替换吗？

**参考回答：**余弦关注方向，点积同时受方向和模长影响，欧氏距离衡量坐标空间的距离。当两个向量都归一化为单位长度时，点积等于余弦，平方欧氏距离与它们有固定单调关系，因此近邻排序可以对应。没有该条件就不能随意替换。工程中我会核对模型训练目标、输出是否已归一化、数据库距离算子与索引配置是否匹配，并用精确搜索验证候选排序。距离值也不是事实正确概率，阈值需要按模型、领域与数据分布校准。

**追问：能复用旧模型的相似度阈值吗？**不应默认复用。模型、维度、归一化或语料变化都可能改变分布，必须重做阈值与拒答评测。

### Q5：为什么需要 ANN，又为什么要保留精确搜索基线？

**参考回答：**精确搜索遍历候选向量并计算距离，逻辑清晰，但大规模和高并发下成本可能过高。近似最近邻用索引结构减少搜索范围，以一定的漏召回换取资源或延迟收益。这里的近似误差是相对于同一向量空间中的精确近邻，不等于相对于业务相关文档的漏召回。我会分别测 ANN 对精确 top-k 的召回、以及全链路对人工相关证据的召回，再观察 p95 与内存。小数据集先用精确基线，避免尚未解决表示问题就调大量索引参数。

**追问：向量精确 top-k 全找到了，业务 Recall 就为 1 吗？**不是。表示模型可能把真正相关文档排到很后面；算法找近邻正确与语义检索正确是两层问题。

### Q6：HNSW 的直观机制与主要取舍是什么？

**参考回答：**HNSW 建立多层邻近图，先在稀疏高层较快定位区域，再在低层细化搜索，避免每次遍历全部向量。图的连边数量、构建搜索宽度和查询搜索宽度会影响内存、建索引时间、召回与延迟。查询探索更多候选通常更费时，但效果仍依赖数据分布和实现。它不是固定复杂度或无损召回的承诺。工程中还要评估增量插入、删除、持久化、并发与过滤的实际支持，并在真实权限过滤和数据规模下测量，而不只跑无过滤演示。

**追问：删掉一条记录后索引一定立即回收内存吗？**不一定，可能是墓碑或延后整理；删除可见性与物理回收要分别查实现和版本。[HNSW 原论文](https://arxiv.org/abs/1603.09320)

### Q7：IVF 和 PQ 分别解决什么问题？

**参考回答：**IVF 把向量划分到若干粗聚类或倒排桶，查询时只搜索部分桶，以减少扫描范围；PQ 把向量分段并用码本编码，用较小存储近似距离。两者可以组合，但减少扫描与压缩表示引入的误差来源不同。搜索桶数更多可能改善召回却增加延迟，压缩更强可能节约内存却损害排序。索引训练样本还需要代表实际数据。我会以未压缩精确搜索为参照，逐项比较召回、内存、构建和更新成本，避免把省内存直接写成质量无损。

**追问：数据分布变了怎么办？**监测各桶负载与召回分桶指标，必要时重新训练或重建索引，并做版本化切换。[Faiss 索引说明](https://github.com/facebookresearch/faiss/wiki/Faiss-indexes)

### Q8：混合检索为什么常用 RRF？

**参考回答：**词法和向量检索的原始分数通常不在同一标度，直接相加可能让某一路长期支配结果。RRF 根据排名累加贡献，不要求原始分数可比，适合作为简单且容易检查的融合基线。但它会丢掉分数差距，结果受候选深度、常数和重复文档处理影响，不能保证优于经校准的加权融合。我会统一文档标识，先去重再比较 RRF、单路检索和其他融合，在查询类型分桶后判断增益，同时统计额外查询的成本与延迟。

**追问：两路都返回同一块，是重复还是加分？**跨列表出现是融合支持信号，可以累加；同一列表里的重复项应按既定规则去重，防止重复灌水提高分数。

### Q9：reranker 为什么可能提高质量，又为什么不能包治百病？

**参考回答：**双塔检索分别编码问题和文档，便于预计算并从大库召回；交叉编码重排器联合处理问题与候选内容，可以学习更细的交互，却通常需要对候选逐个或分批计算。因此适合在有限候选上重新排序。它只能处理已召回内容，必要证据未进入候选时无法凭空补齐。上线前我会核对输入长度截断、语言和领域适配，并比较重排前后的证据覆盖、延迟与费用。若发往外部服务，权限和敏感数据策略必须在外发前生效。

**追问：rerank 分数可以直接当置信度吗？**通常不能。模型分数的标度与任务有关，需要校准和拒答评测。[BERT 重排论文](https://arxiv.org/abs/1901.04085)

### Q10：查询改写和多路查询有什么收益与风险？

**参考回答：**查询改写可以补全对话指代、拆开复合问题或转换领域表达，多路查询能覆盖原问句没有直接出现的术语。但模型可能改掉时间、主体、否定条件或精确编号，把问题变成更好检索却不再正确的问题。我会保留原查询，限制可改写字段，固定标识和权限条件，记录改写轨迹，并把原查询结果纳入融合。多查询需要预算、去重与超时控制；评测既看召回增益，也检查是否产生问题漂移，以及新增耗时是否符合用户等待目标。

**追问：可以让模型生成 tenantId 一起检索吗？**不能信任这种值。租户和访问范围来自服务端身份上下文，模型改写只处理允许修改的查询内容。

### Q11：怎样选择 chunk 大小、重叠和父子块？

**参考回答：**分块应保留完成任务所需的语义单元，如条款、章节、函数或表格行，而不是先选一个统一字数。块太小可能丢条件，太大又会稀释匹配并占用上下文。重叠能缓解边界切断，但会增加索引、重复证据与评测去重难度。父子块可用小块召回，再扩展到带背景的父段落；扩展同样必须受权限和 token 预算约束。我会结合查询类别比较证据完整率、检索与生成效果，并保存源文档位置，使引用能够回到原始版本。

**追问：重叠是不是越大越好？**不是。高度重复会挤占候选与上下文，还可能把一份证据误算为多份独立支持。

### Q12：表格、PDF 和代码为什么不能直接按换行切块？

**参考回答：**表格的数值依赖行列标题、单位和脚注，PDF 的视觉阅读顺序可能不同于提取顺序，代码则依赖符号、调用关系和作用域。简单按换行切块会产生文本仍可读但语义已错的资料，后续模型可能自信使用错误证据。我会保留结构与来源坐标，给表格块补充必要表头，给代码块记录文件、符号和版本，并对解析结果抽样核对。OCR、解析和检索分别建立失败标签，避免把资料抽取错误当成生成模型幻觉后反复调提示。

**追问：把整张表转成自然语言就一定更好吗？**不一定，转换可能丢精度或引入解释；保留原始结构并按问题选择表示，尤其要核对单位、合并单元格和空值含义。

### Q13：知识更新、删除和 embedding 换版如何设计？

**参考回答：**我把源文档、解析结果、分块和向量都带上稳定标识与版本，通过可重放任务更新派生索引。删除与撤权先让在线访问失效，再处理异步索引清理和缓存失效，并监测完成时延。换 embedding 模型通常需要重编码，也可能改变维度、距离和阈值，因此采用新旧版本隔离、离线评测、影子流量和可回滚切换。不能把不同语义空间的向量直接混查，也不能用重新入库成功掩盖旧版本仍被答案缓存或后台任务引用的问题。

**追问：所谓实时删除需要承诺什么？**明确生效点、最长传播时间、在途请求处理和物理清理范围；没有这些边界的“立即彻底删除”难以验证。

### Q14：ACL 过滤为什么会影响召回和缓存？

**参考回答：**授权规则决定哪些候选能进入后续链路，过滤执行位置也会影响召回与耗时。先全局取少量近邻再过滤，可能把候选耗尽；支持带过滤的搜索也需要检查具体执行计划与数据分布。安全底线是未授权内容不能进入用户可见结果或不被允许的外部处理环节。我会把租户、权限版本、知识版本等纳入合适的缓存隔离条件，并在输出前处理权限变化。权限规则来自可信服务端，不能由模型自行判断，也不能只过滤最终展示的引用。

**追问：一个租户只有很少文档时如何优化？**评估先确定允许集合后精确搜索，或增加受控候选探索；必须实测，不能照搬无过滤 ANN 的参数。

### Q15：Recall、Precision 和 MRR 分别回答什么？

**参考回答：**Recall 衡量已标注相关证据中找到了多少，Precision 衡量取回结果中相关的比例；MRR 则对每个查询第一个相关结果的倒数名次求平均，关注首个命中位置。三者需要固定相关性定义和计分粒度。一个需要两份材料的问题只命中其中一份，MRR 可能很好，证据覆盖却不足；重复块也不能随意重复计数。我会同时报告不同 k 的指标、样本数与分桶结果，并说明标注是否完整，避免把漏标的相关材料当成检索错误。

**追问：MRR 是全部相关文档倒数名次之和吗？**不是。它通常只取每个查询首个相关结果的倒数；未命中按零计，再按查询平均。

### Q16：nDCG 比 MRR 多表达了什么？

**参考回答：**MRR 关注第一个相关结果，而 nDCG 可以利用多级相关标签，评价前若干位置整体排序。它先对相关增益按位置折扣求和，再除以该查询理想排序的分数，使不同查询更可比较。关键不只是公式，还包括相关等级、增益函数、截断位置和无相关答案样本的处理。若高相关证据被排得很后，nDCG 会下降，但它依然不是完整业务成功率。实际报告中我会给出代表性排序和标注说明，防止一个总分掩盖关键政策题的退化。

**追问：nDCG 为 1 就代表系统完美吗？**只代表在该标注、候选与截断口径下排序达到理想值；覆盖不全的标注、生成错误和权限问题仍可能存在。

### Q17：怎样建设能指导迭代的 RAG 评测集？

**参考回答：**我按实际任务采样，并覆盖精确编号、改写、多跳、时效、无答案、冲突资料和权限限制等类型，为每题记录期望行为、必要证据、允许来源和知识版本。先人工校准一批标签，再用自动评测扩大范围，保留争议样本和失败原因。调参集与最终评估集分开，避免不断针对同一小集合优化。比较版本时固定语料与题目，分别看解析、检索、上下文、生成和任务完成，让结果指向可行动的改动，同时报告成本、延迟和样本不确定性。

**追问：线上点赞能替代评测吗？**不能，反馈有选择偏差且不直接等于事实正确；可作为发现案例的信号，再经脱敏、标注与复核纳入评测。

### Q18：GraphRAG 与多跳检索适合什么场景？

**参考回答：**当问题需要跨实体关系连接证据，或总结某个大型语料的共同主题时，图结构和分层摘要可能补充单次向量近邻的不足。多跳流程也可以先检索实体信息，再用得到的受控线索检索下一份证据，但每一步都可能传播抽取错误。GraphRAG 不是给任何数据库加一个图标签就自动可靠。我会先用明确查询验证关系和社区摘要的价值，再计算抽取、索引更新、溯源与权限传播成本；普通局部事实问题可能用更简单的检索方案即可。

**追问：关系边或摘要的权限如何定义？**应依据底层支持材料的授权与派生规则，不能因为是摘要就公开；查询仍需能追溯证据。[GraphRAG 论文](https://arxiv.org/abs/2404.16130)

### Q19：RAG 知识库、长期记忆和会话摘要有什么区别？

**参考回答：**知识库保存可引用的外部资料，长期记忆保存被允许跨会话使用的用户或任务事实，会话摘要则压缩当前交互以适应上下文预算。三者可以共用存储技术，但可信度、保留期限、写入权限和删除要求不同。模型从一次对话推断的偏好，不应自动升级成永久事实；摘要也不能替代原始操作记录。我会为记忆记录来源、时间、作用域、置信与纠错状态，按需检索并过期，发生冲突时优先核对权威来源，而不是无条件相信较新的模型总结。

**追问：记忆越多是否越聪明？**不一定，过期或误写记忆会污染决策，还增加隐私与上下文成本；写入、检索、更新和删除都需要评测。

### Q20：怎样向面试官解释一条可上线的检索链路？

**参考回答：**我先说明业务问题、资料更新频率、访问边界与成功标准，再画出入库解析、版本化索引、带权限混合召回、重排、证据组装与生成校验。每个阶段都有可追踪的输入版本和失败标签，无充分证据时按产品约定澄清或拒答。部署选择根据规模、时延与团队运维能力决定，不默认引入所有高级组件。最后用基线对照说明哪些改动改善了哪些题型、增加了多少成本，以及删除、撤权、索引重建和服务故障时如何降级与恢复。

**追问：评测通过却线上退化怎么办？**检查分布、知识版本、权限结构、负载与依赖变化；冻结证据回放并补入失败集，必要时回滚，不用平均分掩盖特定客户的问题。

## L4｜设计与可验证练习

### 练习一：用十几行代码理解 RRF

下列代码只演示排名融合，不代表真实语义检索。列表内去重后重新编号，以文档 ID 作为同分时的确定性次序；生产系统也可选首次原始名次，但需固定口径。

```python
def rrf(rankings, c=60):
    if c < 0:
        raise ValueError("c must be nonnegative")
    scores = {}
    for ranking in rankings:
        unique = list(dict.fromkeys(ranking))
        for rank, doc in enumerate(unique, 1):
            scores[doc] = scores.get(doc, 0.0) + 1 / (c + rank)
    return sorted(scores.items(), key=lambda pair: (-pair[1], pair[0]))

rows = rrf([["A", "B", "A", "C"], ["B", "D", "A"]])
assert [doc for doc, _ in rows] == ["B", "A", "D", "C"]
assert abs(dict(rows)["B"] - (1 / 62 + 1 / 61)) < 1e-12
```

**参考验证：**B 为 `1/62+1/61≈0.032522`，A 为 `1/61+1/63≈0.032266`；D 与 C 只在一路出现。把第二路移除，排序应恢复 A/B/C。新增一条业务必要证据 E，但两路都不返回 E，融合再正确也不能补回它。

### 练习二：亲手算一组分级排序

三个文档的相关等级为 3、2、0，实际顺序为 2、0、3。使用 `2^rel−1` 增益与 `log₂(i+1)` 折扣：实际 DCG 为 `3+0+7/2=6.5`；理想 DCG 为 `7+3/log₂3≈8.8928`，因此 nDCG@3 约为 `0.7309`。交换第一个和第三个文档，再计算分数，解释高价值证据排在前面的收益。

**参考验证：**交换后等级为 3、0、2，DCG 为 8.5，nDCG 约为 0.9558，仍低于理想 3、2、0。若任务必须同时引用两个相关文档，MRR 为 1 仍不能证明生成过程正确引用了两者。

### 练习三：设计一次知识撤权

条件：文档 D 已入两个索引、被答案缓存引用，还在一个正在生成的请求里。写出撤权事件、授权版本、索引墓碑、缓存失效和输出检查的设计；明确哪些动作强一致，哪些动作最终一致。

**参考验证：**至少覆盖新查询不能使用 D、在途输出按明确生效策略阻止泄漏、外部处理和日志符合原有授权、后台清理可重试、物理删除有可审计完成状态。若模型已接收被允许外发的数据，后续撤权不能让历史接收自动消失，必须如实定义边界。
